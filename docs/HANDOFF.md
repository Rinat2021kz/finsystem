## 1. Что это за проект

Управленческая финансовая система для малого бизнеса Казахстана (валюта — тенге).
Клиент вносит простые операции (доход / расход / перевод), система сама считает ДДС, ОПУ,
баланс денег, отчёты по проектам, планы и инвестиционные модели. Клиент не видит формул.
Это же — рабочий кабинет финансового консультанта, ведущего несколько компаний.

**Владелец проекта не разработчик.** Деплой, миграции и команды выполняй сам либо давай
пошаговые инструкции в чате. Не предлагай ему «запустить локально» — у него нет `.env`
и локальной БД (проверено: файла `.env` в репозитории нет, вся работа идёт через прод).

## 4. НЕНАРУШАЕМЫЕ бизнес-правила

Они перечислены в `CLAUDE.md`, но повторю четыре, которые ломают корректность чаще всего:

1. **Деньги — только `bigint` в тиынах** (1 ₸ = 100 тиын). Никогда не float. Форматирование только на выводе (`lib/money.ts`).
2. **ДДС ≠ ОПУ.** `dateCashflow` — дата движения денег. `periodPnl` — экономический месяц (первое число месяца). Это разные поля, не смешивать.
3. **Перевод — не доход и не расход.** В сводном ДДС не меняет общий остаток; в отчёте по одному счёту учитывается.
4. **Мультитенантность.** Каждый запрос фильтруется по `companyId` и проверяет членство через `requireTenant()` из `lib/tenancy.ts`.
5. **Никаких ошибок деления.** Знаменатель 0 → `null` и «нет данных», а не ошибка пользователю.
6. **Отчёты по выбранному периоду**, без зависимости расчётов от текущей даты.

### Ключевые модули, которые нужно знать

**`lib/range.ts` — единый период (самое важное из недавнего).**
Один формат query-параметров работает во всех разделах:

```
?preset=month&year=2026&month=7
?preset=quarter&year=2026&part=2
?preset=half&year=2026&part=1
?preset=nine&year=2026
?preset=year&year=2026
?preset=custom&from=2026-03-01&to=2026-04-22
```

Функции: `rangeFromSearchParams(params, defaultPreset)`, `monthsInRange(from, to)`,
`snapToMonths(range)`, `rangeToQuery(range)`, `hasRangeParams(params)`.
UI — `components/RangePicker.tsx` (клиентский компонент, принимает `children` для
дополнительных фильтров раздела, чтобы они не терялись при смене периода, и флаг
`monthsOnly` для подсказки об округлении).

**Важно:** ОПУ живёт по `periodPnl`, то есть по целым месяцам. Произвольный диапазон дат
в ОПУ округляется через `snapToMonths` — период «17 марта — 22 апреля» превращается в
«Март 2026 — Апрель 2026». В ДДС, балансе, счетах и операциях произвольные даты работают
как есть, потому что там дата платежа.

**`lib/calc/` — расчётное ядро, чистые функции, покрыты тестами:**
`cashflow.ts` (`cashflowSummary`, `cashflowForAccount` — оба принимают произвольные даты),
`pnl.ts` (`pnlForMonth`, `pnlForMonths` — накопительный итог за диапазон),
`balance.ts`, `projects.ts` (`projectMetrics`), `sales.ts`, `expenses.ts`,
`investments.ts`, `calculators.ts`,
`cost.ts` (`componentCostMinor`, `unitCostFromComponents`, `costAtDate`,
`soldGoodsCostMinor`, `averageUnitPriceMinor`).

**`lib/demo.ts` — демо-режим.** Кнопка «Посмотреть демо-кофейню» на `/login` вызывает
`ensureDemoCompany()`; кнопка на дашборде — `resetDemoCompany()` (полный пересоздание).
Логин демо: `demo@finsystem.kz` / `demo2026`. Генерация детерминированная (`mulberry32`),
данные: январь 2025 — июнь 2026, ~700 операций с сезонностью, примеры ДДС ≠ ОПУ
(аренда авансом, зарплата за прошлый месяц, квартальные налоги), переводы-инкассации,
капзатраты, 4 проекта (один с долгом), рецептура, история себестоимости со ступеньками
роста цен, планы 2026, инвестсценарий, закрытые январь–февраль 2025,
share-токен `demo-arman-2026`.

**Миграции:** `0_init`, `1_plans_investments`, `2_product_components`,
`3_transaction_product`, `4_product_cost_history`, `5_warehouse`.

**`lib/calc/stock.ts` — складской учёт (добавлен 2026-08-17).**
Модуль включается флагом `Company.stockEnabled` (страница `/settings/company`,
там же теперь переключаются проекты и инвестиции — раньше это задавалось только в онбординге).

Модель: `Warehouse` (склад/точка) и `StockMove` (движения: `receipt`, `issue`,
`transfer`, `writeoff`). Остатки и себестоимость **не хранятся** — считаются на лету:

- количество ведётся **по складам**, себестоимость — **по FIFO в целом по компании**;
  где лежит товар и по какой цене куплен — независимые измерения;
- `transfer` не меняет ни общий остаток, ни себестоимость (аналог правила 3 для денег);
- если расходу не хватило партий, себестоимость не выдумывается: `uncoveredQuantity`,
  а в UI — «нет данных» и предупреждение, что прибыль завышена;
- `cogsInRange` всегда прогоняет FIFO с начала истории и потом отбирает расходы периода;
- количества считаются в целых тысячных (`Decimal(14,3)`), без float.

**Себестоимость признаётся при продаже, а не при закупке.** Расход с оприходованием
товара (`Transaction` + `StockMove` типа `receipt`) получает `includeInPnl: false` и
`periodPnl: null`; в ОПУ вместо него появляется строка «Себестоимость проданных
товаров» из `pnlForMonths(txns, months, { goodsCostMinor })`. Без склада `goodsCostMinor`
равен 0, и ОПУ считается ровно как раньше — это закреплено тестом.

`projectMetrics` принимает третьим аргументом себестоимость материалов, списанных на
проект (`loadProjectMaterials` в `lib/stock.ts`).

Страницы: `/stock` (остатки), `/stock/moves` (журнал + формы), `/stock/[productId]`
(карточка: остатки, открытые партии, история), `/settings/warehouses`, `/settings/company`.

У `Product` появились `productGroup`, `isSellable` (товар или материал) и `tracksStock`.
Материалы не показываются в плане продаж и в форме дохода.

Демо-кофейня содержит склад (две точки + кухня-склад, четыре материала с партиями по
растущим ценам, списания на проекты). Старую демо-компанию нужно пересоздать кнопкой
«Сбросить демо-данные к исходным».

**История себестоимости** (`product_cost_history`): записи «с какой даты действует эта
себестоимость единицы». `costAtDate(history, date)` возвращает `null`, если продажа
произошла раньше первой записи — интерфейс показывает «нет данных» и предупреждает, что
маржа завышена, вместо подстановки сегодняшней цены задним числом. Карточка продукта
показывает последнюю по дате запись (`syncCurrentCost` в
`app/(app)/settings/products/[id]/actions.ts`).

## 6. Что осознанно НЕ сделано

Не начинай это без явной просьбы владельца — решения приняты и объяснены ему:

- **Фильтр периода в «Инвестициях».** Инвестмодель — сценарий с горизонтом от `startMonth`,
  а не поток фактических операций; фильтровать там нечего.
- **Версионирование самой рецептуры.** Вместо этого расчёт по составу записывается в
  историю себестоимости с датой вступления в силу — проще и достаточно.
- **Дашборд остался на старом `PeriodPicker`** (выбор месяца). Это месячный снимок с
  светофорами, диапазон там не нужен. `components/PeriodPicker.tsx` используется только
  дашбордом и публичной страницей `/share/[token]`.
- **Серверный PDF.** Сейчас печать через браузер (`components/PrintButton.tsx`) —
  осознанный компромисс MVP. Это единственный непокрытый пункт SPEC.
- **Всё из раздела «Чего НЕ делать в MVP» в `CLAUDE.md`** (импорт банковских выписок,
  налоговый калькулятор, полный бухбаланс, мультивалютность, интеграции банков,
  распознавание чеков, боты) — это v3.
